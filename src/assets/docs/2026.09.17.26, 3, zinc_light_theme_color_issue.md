# Zinc-light theme color issue
_Exported on 9/17/2026 at 21:08:40 PDT from Cursor (3.21.9)_

---

**User**

Something strange is happening with the colors of certain elements, as shown in the attached screenshot. 
When the "zinc-light" theme is selected and the app is set to Light mode, the text in some blocks and the arrowheads become almost invisible. 
However, if the app switches to the dark theme, these elements become visible. 
The color of these elements should not depend on the theme selected in the app.

**Cursor**

The diagram colors should stay with the selected diagram theme, not the app light/dark mode. I’ll trace how zinc-light styles text and arrowheads, then isolate them from the app theme.

The SVG is injected as HTML, so I’ll inspect how beautiful-mermaid assigns fills and whether app CSS is overriding named-theme colors.

Named zinc-light leaves `--accent` and `--muted` unset, so they inherit shadcn’s near-white tokens and wash out labels and arrows. I’ll pin those variables on the SVG so the diagram palette stays independent of the app theme.

Yes/No labels and arrows are visible in light mode now. Next I’ll switch to zinc-light and check the same diagram in both app themes.

Those missing Yes/No labels and arrowheads were picking up the **app** theme, not zinc-light.

beautiful-mermaid styles arrows and edge labels with `--accent` and `--muted`. zinc-light only sets `--bg` and `--fg`, so those other variables were inherited from shadcn:

- Light app: `--accent` / `--muted` are nearly white → invisible on a white diagram
- Dark app: they become dark gray → visible again

Node labels like “Ship it” stay visible because they use `--fg`, which zinc-light does set.

The SVG now pins any unused diagram color to `initial`, so the library’s own mixes from `--bg`/`--fg` apply. Named themes that already define accent/muted (tokyo-night, etc.) keep those colors.

Checked in the browser: zinc-light Yes/No text and arrowheads stay the same in both Light and Dark app modes, including the export preview.
