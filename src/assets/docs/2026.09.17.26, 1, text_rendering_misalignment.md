Courier New is the problem: `┆` is a different width than `│`/`─`, so columns drift. Cascadia Mono keeps every glyph on one advance, which is why the editor stays aligned. I’ll switch the preview to that and pin each character to a 1ch cell, the same way Monaco does.

Cascadia keeps every glyph at 7.031px, so columns already line up. I’ll drop the per-character spans (they break selecting text) and check the exact ASCII from the comment.

The generated text is fine. Cursor and the preview are not drawing it the same way.

**Cursor’s editor (Monaco) is a grid.** It measures one cell width (usually `M` or `0`) and puts character *n* at `n × cellWidth`. A glyph can be missing, dashed, or a fallback from another font — it still sits in the same column.

**An HTML `<pre>` is a typesetter.** It adds up each glyph’s real advance. “Monospace” does not mean every Unicode character is the same width. At 12px on this machine:

| Character | Courier New (what the preview used) | Cascadia Mono |
|---|---|---|
| `M` `─` `│` | 7.201px | 7.031px |
| `┆` (dashed vertical) | **6.598px** (or 12px if it falls back) | 7.031px |
| `▼` `◄` `►` | mixed / fallback | 7.031px |

Geist Mono has the same class of bug in the other direction: letters are 7.2px, box-drawing (`│` `─`) come from a second file at **8.502px**.

That is the “baffling” misalignment. Two `┆` on a line steal about 1.2px from everything after them, so the next row’s `│` no longer sits on the same x. The stem looks broken, and at a `┼` it looks like a slight overlap. Thick verticals are the other half: latin and box-drawing faces have different ascent/descent, so some rows are taller and `│` ink stacks.

**Fix:** the Text preview now uses Cascadia Mono (the same family as Windows Terminal / VS Code), with latin + box-drawing loaded as one family, and each row locked to `1em` so the stems meet. Measured after the change: every diagram character is 7.031px, and every row is the same width. The editor font is still Geist Mono.
